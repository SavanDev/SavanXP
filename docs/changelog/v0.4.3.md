# SavanXP 0.4.3

## [0.4.3] - 2026-11-17

### Added

- **Images open in Image Viewer by default; Edit opens Paint from Files and the desktop.**
  BMP/PNG/JPEG defaults respect each user's `assoc.ini`; the table now holds 64 extensions.
  Menus skip disabled actions with the keyboard; Paint's format support is unchanged.

- **Image Viewer opens BMP, PNG and JPEG with native SUN controls and house-style icons.**
  Fit, actual size, zoom, pan, folder navigation, Open and fullscreen are available from Accessories or `imgview`.
  See [IMAGE_VIEWER.md](../desktop/IMAGE_VIEWER.md).

- **Desktop wallpapers and Display Properties now open JPEG through the common image API.**
  `.jpg`/`.jpeg` join the list and Browse; large sequential JPEGs reduce to fit the 2048-side output limit.
  Image Viewer roadmap I5 is complete; see [DISPLAY_PROPERTIES.md](../desktop/DISPLAY_PROPERTIES.md).

- **`libsximg` decodes JPEG at 1/2, 1/4 or 1/8 resolution without a full-size bitmap.**
  Automatic scale selection fits output limits; exact scales and source/output dimensions agree across both image APIs.
  Larger JPEG sources can fit at a reduced scale; see [IMAGE_FORMATS.md](../media/IMAGE_FORMATS.md#limits-and-scaling).

- **`libsximg` decodes RGB/YCbCr JPEG with JFIF and Adobe colour transforms.**
  Sampling factors 1/2, interleaved and separate scans, and restart intervals are supported at full resolution.
  See [IMAGE_FORMATS.md](../media/IMAGE_FORMATS.md#sequential-jpeg) for the supported subset.

- **`libsximg` decodes sequential 8-bit greyscale JPEG through `sx_jpeg_info`, `sx_jpeg_decode_into` and the common image API.**
  SOF0/SOF1, restart markers and full-resolution output are supported, with named rejection errors;
  see [IMAGE_FORMATS.md](../media/IMAGE_FORMATS.md#sequential-jpeg) for the supported subset.

- **`libsximg` adds common BMP/PNG decoding with `sx_image_format`, `sx_image_info` and `sx_image_decode_into`.**
  Callers can set output limits and receive source/output dimensions, scale and named errors.
  See [IMAGE_FORMATS.md](../media/IMAGE_FORMATS.md) for format coverage and the decoding contract.

- **Paint, desktop wallpapers and PNG cursors now read indexed and greyscale PNGs, all legal sample depths, `tRNS` and Adam7.**
  `libsximg` retains straight alpha for cursors, composites documents onto white, and rescales 16-bit samples to 8 bits.
  Incomplete PNGs and unsupported critical chunks are rejected.

- **Paint and desktop wallpapers now read paletted, 16-bit, masked and RLE4/RLE8 BMPs, including V4/V5 alpha.**
  `libsximg` composites alpha onto white; `sx_bmp_decode_argb_into` preserves it for callers.
  Image Viewer roadmap phase I3 is complete.

- **SSL runs the original Alpine Xeyes from Start and by double-clicking its ELF in Files.**
  `install_xeyes.py` installs its pinned runtime persistently; `x11d` adds child windows and icon pixmaps.
  `linux-xeyes` checks Linux reference pixels, pointer tracking, resize, relaunch and restart; see [LINUX.md](../userland/LINUX.md).

- **SSL displays the unchanged Alpine Xlib `xclient` in a desktop window through the SUN `x11d` service.**
  Local stream sockets, `poll`, pointer queries, drawing, resize and caption close are covered by `linux-xclient`.
  SUN `sxnwm_query_pointer` and POSIX `gfx_query_pointer` expose desktop pointer snapshots; see [LINUX.md](../userland/LINUX.md).

- **SSL runs the unchanged dynamic Alpine `jq` and its musl libraries, including shared-library TLS.**
  `linux-dynamic` covers private file maps, `mprotect`, 320 simultaneous mappings and missing runtime files.
  Linux launches now report a missing interpreter as `ENOENT`; see [LINUX.md](../userland/LINUX.md).

- **SSL runs Alpine's unchanged static BusyBox `echo`, `cat`, `ls`, `pwd`, `wc` and `mkdir`.**
  `linux-tools` checks Linux reference output, directory enumeration, working directories, creation masks and errors.
  See [LINUX.md](../userland/LINUX.md).

- **PNG wallpapers: Display Properties lists the `.png` files in `/wallpapers` and Browse accepts a PNG; the desktop
  reads 8-bit RGB and RGBA PNGs, told from BMPs by their contents.** `libsximg` adds `sx_png_info` and
  `sx_png_decode_into`. See [DISPLAY_PROPERTIES.md](../desktop/DISPLAY_PROPERTIES.md#the-configuration).

- **Files has Cut, Copy and Paste (Edit menu, toolbar, context menus, Ctrl+X/C/V) for one file or folder at a time.**
  A copy into a taken name becomes "Copy of ...", a move across volumes copies then removes, a cut item is drawn faded,
  and a paste longer than half a second shows a progress dialog with Cancel. See
  [FILES.md](../desktop/FILES.md#cut-copy-and-paste).

- **The clipboard holds several formats of one content, named by media type, and its capacity rises from 8 KiB to
  1 MiB.** `CLIP_IOC_SET_FORMATS` replaces the whole set or leaves it intact, `CLIP_IOC_GET_FORMAT` and
  `CLIP_IOC_ENUM_FORMAT` read it; POSIX `clipboard_set_formats`, `_get_format`, `_enum_format`. Plain text is
  `text/plain;charset=utf-8` and keeps working through `read`/`write`. See [CLIPBOARD.md](../desktop/CLIPBOARD.md).

- **A program can wait for the clipboard to change: a `/dev/clipboard` descriptor is readable (`poll` `POLLIN`,
  `sxn_wait_io`) while the content changed since it last called `CLIP_IOC_GET_INFO`.** See
  [CLIPBOARD.md](../desktop/CLIPBOARD.md#following-changes).

- **The SxGUI toolkit reaches the clipboard's formats from POSIX and SUN programs alike:
  `sxgui_clipboard_set_formats`, `_get_format`, `_enum_format`, `_has_format`, over a new host table
  (`struct sxgui_host_clipboard`).** Programs built before it keep text only. See
  [PLATFORM_GRAPHICS.md](../desktop/PLATFORM_GRAPHICS.md#the-clipboards-formats).

- **Media Player supports fullscreen with a Fullscreen button and F11; Esc or F11 restores the window.**
  Video keeps its aspect ratio, playback continues, and controls and desktop chrome are hidden.
  SUN and POSIX windows can request fullscreen at desktop resolution.

- **When a library version a program names is missing and the loader falls back to the newest minor, the system log
  records it (`loader: libfoo.so.0.4 is not in /lib; falling back to the newest, libfoo.so.0.6`), from SUN and POSIX
  alike, whatever standard error is.** Scenario `posix-loader-log`; see [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md#dt_soname-resolution).

- **POSIX programs can write to the system log: `syslog(3)` (`<syslog.h>`), over `SXN_SYS_LOG`, now open to every
  subsystem; its lines read `posix[pid]: ...`.** Scenario `posix-syslog`; see [SYSTEM_LOG.md](../kernel/SYSTEM_LOG.md).

- **A needed library resolves to the exact `/lib` file, else its highest newer minor (`0.6` for `libfoo.so.0.4`), never an
  older one; a name without a full version (`libfoo.so`, `libfoo.so.0`) gets the latest, in `DT_NEEDED` or a bare
  `dlopen`.** Scenarios `sonametest`, `sonametest-newer`; see [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md#dt_soname-resolution).

- **POSIX programs can list a directory through the native calls, `sxn_open_directory` and `sxn_read_directory`
  (`SXN_SYS_OPEN_DIRECTORY`, `SXN_SYS_READ_DIRECTORY`); the handle is a descriptor.** `handletest` asserts it.

- **SUN programs can map shared libraries: `savanxp_program(NATIVE)` takes `LINK_PROFILE PIE` and `DEPENDS`, through the
  loader POSIX uses, now `system/loader/ldso.c`; `<dlfcn.h>` is POSIX's layer over it (`include/loader/loader.h`).**
  The `sun-libtest` scenario maps `libmath` from SUN. See [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md#one-loader-over-sxn).

- **POSIX programs can open a file through the native call, `sxn_open_file` (`SXN_SYS_OPEN_FILE`), and use the handle
  as a descriptor or back a section with it.** `handletest` asserts it. See
  [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md#one-loader-over-sxn).

- **SUN programs can map a range of a file as a read-only section, `sxn_section_open_range` (`SXN_SYS_SECTION_OPEN_RANGE`),
  shared system-wide with the POSIX `section_open_range`; a range outside the file is now `EINVAL` in both, not
  `ENOMEM`.** The first slice of one loader for SUN and POSIX; see [SECTIONS.md](../kernel/SECTIONS.md).

- **SSL L2 closes: a static musl program gets files and clocks, with `open`, `read`, `close`, `lseek`, `stat`, `fstat`
  and `unlink` on a descriptor table of its own under `/system/linux`, and `clock_gettime` and `nanosleep`.**
  `linux-hello` adds the `clock` and `files` fixtures; the new `linux-restart` scenario reads a Linux program's file back
  after a guest restart. See [LINUX.md](../userland/LINUX.md).

- **Anonymous memory regions (S2a) and SSL L2's memory half: a static musl program runs unchanged, with `mmap`,
  `munmap`, `mremap` and `brk` over `vm::map_region` and friends, whose pages appear zeroed on first touch.**
  `arch_prctl(ARCH_SET_FS)`, `set_tid_address`, `writev` and `ioctl` work too; `linux-hello` adds the `regions`, `args`,
  `tls` and `heap` fixtures and `region-list-test` the list's host tests. See
  [MEMORY_REGIONS.md](../kernel/MEMORY_REGIONS.md) and [LINUX.md](../userland/LINUX.md).

- **SSL L1: `linux [-e NAME=VALUE]... GUEST_PATH` runs a static Linux x86-64 executable from `/system/linux` unchanged,
  with Linux's start-up stack; `write`, `exit` and `exit_group` work and every other call answers `-ENOSYS`.** SUN
  programs reach it through `SXN_SPAWN_FLAG_SUBSYSTEM` (`sxn_spawn_ex_subsystem`). `linux-hello` compares three
  fixtures byte for byte with Linux. See [LINUX.md](../userland/LINUX.md).

- **SSL E1: the kernel clears EFER.SCE on every processor, so `syscall` raises #UD; a subsystem can claim it with
  `subsystem::register_trap_dispatcher`, and Linux (`subsystem::Id::linux`) answers every call `-ENOSYS` for now.**
  A native or POSIX `syscall` still ends the process with status 134. See [LINUX.md](../userland/LINUX.md).

- **SSL (Savan Subsystem for Linux) L0: `subsystems/linux/profile/profile.sh` rebuilds the pinned Alpine 3.24 profile
  unprivileged, builds the L1-L5 fixtures with the host clang against musl only, and traces them and Xeyes on Linux.**
  Reference outputs are under `subsystems/linux/profile/expected/`; see [LINUX_XEYES_PROFILE.md](../userland/LINUX_XEYES_PROFILE.md).

- **NVMe storage driver `nvme`, adapted from OpenBSD `nvme(4)`: every 512-byte namespace registers as `nvmeN`, and the
  drive gets a shutdown notification before power-off or reboot (`block::shutdown_all`).** NVMe disks are read-only
  unless the boot entry carries `nvme-rw`; `SAVANXP_DISK_BUS=nvme` puts QEMU's disk on NVMe. Not yet run on metal. See
  [NVME.md](../kernel/NVME.md).

- **System Properties has a Licenses tab: every component under `/system/licenses`, SavanXP first, with its notice
  and full license text.** An installed port appears on its own; F5 rescans.

- **License notices in the image: `/system/licenses/<id>/` holds a `NOTICE` and the full license texts of every
  third-party component, staged from `assets/licenses/*.notice` by the build and from `ports/<name>/licenses/` when a
  port is installed.** `license-notices-test` fails if a shipped registry entry has no notice. See
  [LICENSE_NOTICES.md](../third-party/LICENSE_NOTICES.md).

- **Ethernet driver `rtl8168` for the Realtek RTL8111/8168 family (`10ec:8168`, `8161`, `8136`, `8169`, `8167`),
  adapted from OpenBSD `re(4)` under its BSD-4 license; boot logs `rtl8168:` with the chip revision and MAC.** Not yet
  run on metal (QEMU has no model). See [REAL_HARDWARE.md](../hardware/REAL_HARDWARE.md#hw-1--realtek-rtl811181688101).

- **SMAP: on a CPU that has it, every core sets `CR4.SMAP` and the kernel touches user memory only inside
  `arch::user_access_begin`/`user_access_end`; a stray access stops the system with `SMAP violation`.** Without it the
  boot logs `cpu: SMAP unavailable on this processor`. See [KERNEL_SECURITY.md](../kernel/KERNEL_SECURITY.md#user-access-windows-smap).

- **Pin to the Start menu: Files' item menu has Pin to Start Menu for programs, `.exe` files and shortcuts, and a right
  click on a pinned row offers Unpin from Start Menu.** The pins are the user's `Start Menu` folder, seeded once from
  `/system/start`; a `.exe` is named by its version resource's `FileDescription` (`sxgfx/pe_version.h`). See [START_MENU.md](../desktop/START_MENU.md#shortcuts).

- **Windows XP Solitaire runs: the user's own `sol.exe` and `cards.dll` in `C:\Program Files\Solitaire` open from Files
  (`.exe` is associated with `winhost`) and from a Solitaire shortcut in the Start menu, with their own icon.** The Start
  menu lists the `.sxlnk` shortcuts pinned in `/users/user/Start Menu` above Programs. `win32-solitaire-test`
  and smoke scenario `win32-solitaire` win a recorded game, skipped (77) without the files. See
  [WIN32.md](../userland/WIN32.md#solitaire).

- **Win32 menus and dialogs: menu bars and popup menus by pointer and keyboard, `DialogBoxParamW` with its keyboard
  interface, the Button and Static controls, `MessageBoxW`, and new `shell32.dll` (`ShellAboutW`) and `comctl32.dll`
  (`InitCommonControlsEx`).** Dialogs and menus are `windowd` owned windows (private ABI v4); smoke scenario
  `win32-dialog` checks them against Windows XP. See [WIN32.md](../userland/WIN32.md#menus-dialogs-and-controls).

- **Win32 bitmaps and resources: memory device contexts, `BitBlt`, `StretchBlt` and monochrome/colour conversion in
  `gdi32.dll`; `LoadBitmapA`, `LoadStringW`/`A`, `LoadIconW`, `LoadImageW`, `LoadAcceleratorsW` and
  `TranslateAcceleratorW` in `user32.dll`.** The user's own Windows XP `cards.dll` draws every card as on Windows XP;
  smoke scenario `win32-cards` checks it and is skipped (77) without `SAVANXP_WIN32_FIXTURES`. The build needs
  `llvm-rc`. See [WIN32.md](../userland/WIN32.md#user32-and-gdi32).

- **Win32 programs open windows: `user32.dll` and `gdi32.dll` for windows, messages, painting, timers and input, the
  top-level window a `windowd` window under `winhost`.** `win32-harness --input` drives a fixture from a script; smoke
  scenario `win32-window` checks messages and pixels against Windows XP. See [WIN32.md](../userland/WIN32.md#user32-and-gdi32).

- **Win32 base runtime: `msvcrt.dll` and `advapi32.dll`, and `kernel32.dll`'s module, memory and command-line functions,
  so a program that starts like Windows XP Solitaire runs under `winhost`.** HKCU lives in `/users/user/Settings/win32.reg`;
  `winhost --registry` and `--time` choose another file and fix the clock. See [WIN32.md](../userland/WIN32.md).

- **SUN programs can read the date: `sxn_system_time()` (`SXN_SYS_SYSTEM_TIME`), seconds since 1970 UTC, the clock POSIX
  `realtime()` and file times use.**

- **PE32 console programs run on SavanXP: `/system/winhost.sxe program.exe`, with the subsystem's `ntdll.dll` and
  `kernel32.dll` in `/system/win/drive_c/windows/system32`.** Smoke scenario `win32-hello` checks the fixtures against
  Windows XP's output and exit status. See [WIN32.md](../userland/WIN32.md#winhost--subsystemswin32host).

- **Native programs can run 32-bit code: a ring-3 32-bit code segment (`0x2b`) and per-thread DS, ES, FS and GS.**
  User data `0x1b` is now a valid 32-bit stack segment, TSS selectors start at `0x30`, and `int 0x80` from 32-bit code
  returns `-ENOSYS`. See [ARCH.md](../kernel/ARCH.md#segments).

- **Native programs can map a section view at a chosen address: `SXN_SYS_MAP_VIEW_AT` (`sxn_map_view_at`), the native
  side of POSIX `map_view_at`.** At a fixed base, both now answer `-EEXIST` for an occupied range and `-EINVAL` for one
  outside the user half, instead of `-ENOMEM`. See [SECTIONS.md](../kernel/SECTIONS.md#map_view_at-and-why-a-loader-needs-it).

- **Win32 subsystem on the build host: PE32 parser, loader, `ntdll.dll` and `kernel32.dll`, and `savanxp-win32-harness`,
  which runs PE32 executables on Linux x86-64 through a 32-bit gate.** Fixtures (`hello.exe`, `initorder.exe`) give the
  same bytes and exit statuses as on Windows XP; tests `win32-pe-test`, `win32-harness-test`, and `win32-pe-fixtures-test`
  for the user's `sol.exe` and `cards.dll` (`SAVANXP_WIN32_FIXTURES`). The build now requires `lld-link` (from `lld`).
  See [WIN32.md](../userland/WIN32.md).

- **POSIX programs can change their window title: `gfx_set_title`, the POSIX side of SUN's `sxnwm_set_title`.** Paint
  uses it for `untitled - Paint` and `<file> - Paint`. Subsystems now keep feature parity (`AGENTS.md`).

- **USB on machines from before xHCI: EHCI, UHCI and OHCI drivers, with EHCI handing low- and full-speed devices to
  its companions.** Keyboards, mice, hubs and sticks as on xHCI; device lines now name the controller (`usb: uhci1 port 2`).
  `tools/run_qemu.py --usb-host`, and `uhci-smoke`, `ehci-stick-smoke`, `ohci-hotplug-smoke` and the rest. See [USB_HOST_CONTROLLERS.md](../kernel/USB_HOST_CONTROLLERS.md).

- **The boot log says which machine it ran on: `boot:` (firmware and loader), `cpu:` (vendor, family, model, stepping,
  brand, features) and one `pci:` line per function.** Log Viewer never drops the boot lines, so they are readable on a
  machine without a serial port. See [REAL_HARDWARE.md](../hardware/REAL_HARDWARE.md#reading-the-log-on-the-machine).

- **Common Open and Save As dialogs for SUN programs (`sxn_file_dialog_begin`); Log Viewer saves the log with File > Save Log...**
  New native calls list directories and stream files of any size: `sxn_query_path`, `sxn_open_directory`,
  `sxn_read_directory`, `sxn_create_file`, `sxn_flush_file` (`SXN_SYS_QUERY_PATH` to `SXN_SYS_FLUSH_FILE`).
  See [FILE_DIALOG.md](../desktop/FILE_DIALOG.md).

- **SxGL Diagnostic Tool (`sxgldiag`, System menu): the machine, the display and both SxGL backends on tabbed pages.**
  Test software / Test GPU draw a lit, textured cube, check the frame and report fps; Save All Information writes
  `/users/user/SxGLDiag.txt`; `sxgldiag --selftest` runs it without a window. See [SXGL_DIAG.md](../desktop/SXGL_DIAG.md).

- **Log Viewer (`logview`, System menu) shows the system log without a serial cable, by program and by kernel subsystem.**
  Problems, Find, follow and copy; `logview --print [category]` for the text console. The kernel keeps the first 512
  lines since boot (`SXN_LOG_BOOT_KEPT`) and the latest 1536 for `sxn_log_read` (`SXN_SYS_LOG_READ`). See [LOG_VIEWER.md](../userland/LOG_VIEWER.md).

- **`sxfs-cli recover` and `sxfs-cli repair [--dry-run]` fix an interrupted or damaged SxFS image on the host.**
  Repair works on a copy, keeps the original as `<image>.before-repair` and rescues lost files to `/lost+found`.
  See [SXFS_CHECK.md](../fs/SXFS_CHECK.md).

- **Volumes can be mounted read-only: the "Read-only" box in Disk Management's Mount, `sxn_storage_mount_flags`.**
  Nothing is written to the device and every change fails with `EROFS`; the volume is listed with `SXN_STORAGE_READ_ONLY`.

- **`fsync` and `fdatasync` (`SAVANXP_SYS_FSYNC`) wait until a file or directory is on the medium.**
  Write a temporary, `fsync`, `rename` over the old file, `fsync` the directory: a power cut leaves the old file or the new one.
  See [FILESYSTEMS.md](../kernel/FILESYSTEMS.md#the-file-contract).

- **SUN exposes IPv4 TCP/UDP sockets and cancellable I/O readiness waits.**
  `sxn_wait_io` combines stream interests with events; `smoke native-network` checks the native contract.

- **Nightwood supports F11 fullscreen, and Doom toggles its FPS overlay with F.**
  SUN games can opt into fullscreen with `sxnwm_connect_with_launch_flags`.

- **Windows and the mouse pointer have optional soft shadows, enabled by default.**
  Display Properties → Settings → Effects controls them independently and saves the preferences.

- **Right-clicking an empty area of the taskbar opens a menu with `Task Manager...`.**

- **Mouse Properties selects cursor schemes with previews, licensing, Apply/Cancel and saved preferences.**
  Open it from the desktop menu or System group. Includes SavanXP Classic, Retrosmart and Hackneyed.
  See [CURSORS.md](../desktop/CURSORS.md).

- **SUN can save small complete regular files with `sxn_write_file`, including a volume sync.**
  Saves enforce VFS permissions and retain existing file ownership and permissions.

- **Window corners show diagonal resize cursors in both directions.**
  The selected direction remains visible throughout a resize drag.

- **The compositor reads classic `.cur` files directly, including native hotspots, embedded PNG and AND/XOR masks.**
  `smoke cursor-smoke` checks the loaded cursor images on light and dark backgrounds.

- **SUN programs can open and sequentially read existing regular files with `sxn_open_file`.**
  File handles enforce VFS permissions; query-only opens do not grant read access.

- **Sound remembers device, connector, headphone policy, recording and application settings across restarts.**
  Saved application levels follow trusted user/image/role identities; errors remain visible until saved.
  See [SOUND.md](../media/SOUND.md) and [AUDIO_DAEMON.md](../media/AUDIO_DAEMON.md).

- **Sound can choose playback and recording defaults independently across supported audio devices.**
  Analog HDA keeps separate controller/codec streams; idle devices remain visible for selection.
  See [AZALIA.md](../kernel/AZALIA.md).

- **Sound records and replays a three-second input test, with an input selector, gain, mute and live levels.**
  SUN recording supports shared native capture and direct HDA/virtio-sound duplex operation.
  See [SOUND.md](../media/SOUND.md) and [AZALIA.md](../kernel/AZALIA.md).

- **Sound reports jack connection state and offers optional automatic headphone switching.**
  Unknown readings preserve the output; failed changes are reported without continuous retries.
  Manual output selection disables automatic switching. See [SOUND.md](../media/SOUND.md).

- **Sound lists the effective audio device and connector and can select analog HD Audio outputs.**
  SUN exposes stable endpoint ids; failed changes restore the previous route when possible.
  See [SOUND.md](../media/SOUND.md) and [AZALIA.md](../kernel/AZALIA.md).

- **The SUN Sound panel controls master and application volume, mute and live levels.**
  Open `sound.sxe` from **Sound settings...** in the speaker popup or the System group.
  See [SOUND.md](../media/SOUND.md); `smoke sound-smoke` checks the panel and its controls.

- **Analog HD Audio playback through an OpenBSD `azalia` port.** Confirmed on the Ryzen/ALC892 host.
  `--audio-device hda`, `smoke hda-stream` and `hda-stream-quiet` cover QEMU playback at full/half volume.
  Scope and limits: [AZALIA.md](../kernel/AZALIA.md).

- **virtio-gpu negotiates virgl**: on a device that offers it the kernel reads the capset, logs
  `virtio-gpu: virgl capset=...` and sets `SAVANXP_GPU_INFO_FLAG_3D`. `--gl` (`SAVANXP_GL=ON`) boots
  QEMU with `virtio-vga-gl`; plan in `docs/roadmaps/open/VIRGL_ROADMAP.md`.

- **3D ioctls on `/dev/gpu0`** (`GPU_IOC_3D_GET_CAPSET` to `GPU_IOC_3D_TRANSFER`): per-process virgl
  contexts, section-backed resources, synchronous `SUBMIT_3D` and transfers, freed on exit and
  marked lost (`SX_EIO`) by a device reset. `nativetest` clears a render target on the GPU.

- **SxGL draws on the GPU where virgl exists** (`--gl`), Nightwood and Gears included: the host
  rasterizes and textures, `sxgl_swap_buffers`/`glFinish` read the frame back, and any failure
  falls back to software. `sxgl_context_create_ex(..., SXGL_CONTEXT_SOFTWARE)` opts out;
  `sxgl_context_backend` says which is in use. `smoke sxgl-gpu-test --gl` compares both backends.

- **`SAVANXP_QEMU_STDERR=PATH`** keeps QEMU's stderr during a smoke (virglrenderer's errors).

### Changed

- **Web Viewer now runs on SUN as `/system/webview.sxe`, also launched as `webview`.**
  Its interface, local files, HTTP, DNS overrides, arguments, history and links are preserved;
  the normal build retires its old `/bin` copies while keeping external apps and assets.

- **BMP decoding moves into `libsximg` (`sx_bmp_info`, `sx_bmp_decode_into`), shared by Paint and the desktop
  wallpaper; Paint now also opens 32 bpp BMPs.** See
  [IMAGE_VIEWER_ROADMAP.md](../roadmaps/open/IMAGE_VIEWER_ROADMAP.md#i1--bmp-moves-into-libsximg-done).

- **`cp` runs Files' copy engine: copies keep the source's permission bits, and copying a file or folder onto or into
  itself is refused instead of emptying the file (`cp a a`) or recursing.**

- **Media Player's fullscreen button is now a matching black 16x16 icon to the right of the volume control.**

- **The toolkit libraries split by subsystem: `libgfx2d` (pixels, painter, chrome) and `libsxgui` (the SXGUI core) are
  neutral, `libsxgfx` is POSIX's window client; the six SUN programs that paint now map them, ~80 KB less text each.**
  A SUN PIE program links without `--export-dynamic`. See [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md#the-toolkit-split-into-neutral-and-host).

- **The shared-library loader speaks SXN and calls no C library; its messages are in English and go through the runtime
  hook `sx_loader_report`.** `dlopen` joins a relative path with the working directory itself; `check_shared_libs`
  now fails the build if the loader imports anything else. See [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md#one-loader-over-sxn).

- **`smp-stats` names Linux system calls (`linux#N`) and counts them at the `syscall` door, not the fault door they
  trap through; `top held` has a row per subsystem.** Before, Linux holds were left out of `top held` and the longest
  hold called them `native`.

- **The lowest user address is `0x10000` (`kUserFloor`) for every subsystem, down from `0x400000`.** SDK programs still
  load at `0x400000` (`kUserBase`); a Linux `ET_EXEC` linked lower now loads. See
  [USER_ADDRESS_SPACE.md](../kernel/USER_ADDRESS_SPACE.md).

- **A process may hold 128 section views (was 64) and the system 512 sections (was 256)**, so a Win32 program fits:
  `winhost` maps one section per protection run of each image. See [SECTIONS.md](../kernel/SECTIONS.md#the-budget).

- **Paint looks like the Win9x one:** colour toolbox icons, a brush/eraser size box, the picture in a grey workspace,
  the 28-colour box at the bottom with a foreground/background well (right click sets the background, which the eraser
  paints), position and size panes in the status bar, and `Image > Clear Image`. See [PAINT.md](../desktop/PAINT.md).

- **The ISO boots at the monitor's preferred resolution (EDID) instead of a fixed `1280x800x32`**; a new
  **SavanXP (1024x768)** boot entry forces the VESA mode every video BIOS offers. `run` and the smokes keep 1280x800
  (`boot/limine-dev.conf`).

- **The PCI table holds 256 functions instead of 64**; `pci: table full` counts any that do not fit.

- **Native and POSIX file handles go through one kernel file path**: `sx::open_file`, `read_file`, `write_file`,
  `seek_file` and `close_handle`, with results that carry a status and a length. A read or write that fails partway
  returns the bytes it moved, and a seek past the 64-bit range is `EINVAL` (VFS-A step 1).

- **Open handles and file-backed sections are counted on the vnode** (`vfs::retain`, `vfs::release`, `vfs::is_held`),
  replacing `vfs::set_holder_probe`. A file a live section was read from now survives its unlink until the section goes;
  on FAT that unlink is `EBUSY`.

- **FAT keeps a file open while something holds it**, through the new `fs::Driver::open`/`close` (first and last
  holder): reads go on from where they stopped instead of reopening the file by path and walking its clusters.
  Each write is still on the disk when it returns.

- **A POSIX process's current directory holds its directory**: `getcwd` follows a rename of it, and the directory
  cannot be removed (`EBUSY`) or its volume unmounted while a process stands in it. Renaming a directory someone has
  open or stands in is now allowed. Subsystems get `subsystem::register_process_state_hooks`.

- **FAT volumes publish a directory the first time it is looked into**, not their whole tree at mount
  (`vfs::install_volume_directory`, `fs::Driver::populate`/`forget`): a USB stick with more files than the VFS's
  2048 nodes mounts. A single directory too large for the VFS fails its own lookup (VFS-C slice 1).

- **The VFS gives published directories back when its node pool runs low** (`vfs::trim_if_low` at system-call
  entry), least recently looked into first and never with anything under them held, so visiting a whole large stick
  no longer fills the pool. Kernel code must `vfs::retain` a `Vnode*` it keeps past a system call (VFS-C slice 2).

- **Listing a directory while entries are deleted or added no longer skips any**: `readdir` keeps a cursor the VFS
  moves past a removed entry (`vfs::DirCursor`), each step O(1). `rm -r` now lists each directory once instead of
  reopening it after every deletion (VFS-C slice 5a).

- **A name or path that is too long fails with `ENAMETOOLONG`** (36, `SX_ENAMETOOLONG`), instead of `EINVAL`: past
  the 1023 bytes a system call copies, the VFS's 255-byte names, or a format's own limits (SxFS's 63-byte names).

- **Names can be up to 255 bytes, was 63** (`vfs::kMaxPathComponentLength`): FAT's long names are published whole
  instead of being left out. Names of more than 47 bytes are kept on the heap. SxFS keeps its 63-byte format limit.

- **Paths can be up to 1023 bytes, was 255** (`vfs::kMaxPathLength`, `PATH_MAX` 1024 in the SDK), with up to 64
  components; the kernel keeps them on the heap (`vfs::PathBuffer`). SxFS keeps its 255-byte format limit.

- **Names on FAT volumes are case-insensitive, as FAT is**: `/boot/LIMINE.CONF` finds `limine.conf`, creating
  `Readme` next to `README` opens it, and renaming to another case renames (`fs::Driver::same_name`, VFS-C slice 4a).
  SxFS and the rest of the tree stay case-sensitive.

- **SxFS volumes publish a directory the first time it is looked into too**: a mount publishes only its mount point,
  and an SxFS volume with more entries than the VFS's 2048 nodes mounts and is read whole (VFS-C slice 3).

- **The Start menu cascades: Programs ▸ and Settings ▸ open beside it on hover (400 ms) or click.**
  Display, Mouse, Sound, Add/Remove Programs and System Properties declare `category=Settings` and leave Programs.
  The banner shows the edition only when it fits. See [START_MENU.md](../desktop/START_MENU.md).

- **Shut Down... and Restart... in the Start menu open a Windows 95-style Shut Down dialog instead of arming the footer.**
  Radio buttons choose shutting down or restarting (S/R, arrows), Yes/No answer; Restart... has its own icon.
  The dialog takes the keyboard with the new shell request `SAVANXP_WM_SHELL_TAKE_FOCUS` and No gives it back.

- **`smp-stats:` names who holds the kernel lock.** A third line, `top held`, lists the four syscalls
  with the most time held; `report=` shows what the report cost and keeps it out of the longest hold.
  How to read it, and the plan it serves: `docs/roadmaps/open/SMP_ROADMAP.md`, phase 5.
- **The tray volume popup is redesigned: output device and master slider, one slider per application, and a Sound settings link.**
  Each application shows its window's icon; the speaker beside the device toggles mute. Audiod's snapshot gains each stream's `pid`.
  See [SOUND.md](../media/SOUND.md#volume-popup).

- **Sound is now a classic Sounds and Audio Devices property sheet: Volume, Applications, Audio, Voice and Hardware tabs.**
  OK/Cancel/Apply replace Close; Cancel restores the device levels. See [SOUND.md](../media/SOUND.md).

- **Small disk reads are cached, and a file no longer hits "no space" at 4 MiB when another grows beside it.**
  The block layer keeps 1 MiB of recently read sectors; SxFS moves a file that ran out of extents to one contiguous run.
  `fscheck` and `sxfs-cli check` find a repeated name in one pass.

- **Recognising an SxFS volume no longer writes to it, and host tools accept an image with a pending journal.**
  `sxfs-cli check` validates it as recovered without modifying it; `apply` and `rm` replay the journal first.

- **`rename` onto an existing file or empty directory replaces it atomically on SxFS, and `unlink` works on open files.**
  Open handles keep an unlinked or replaced file's contents until the last one closes; FAT answers `EEXIST`/`EBUSY`.
  File errors are now precise: `EXDEV` across volumes, `EROFS`, `EIO`, `ENOTEMPTY`, `EISDIR`, and a failed read
  is an error instead of an end of file. Deleting files no longer uses up the VFS node pool.

- **Web Viewer's roadmap now targets Ladybird with a native SUN frontend.**
  It pins the pre-Rust C++ baseline `37ec6a08a8aaff5808e5b570430001594692fde3` and discards NetSurf.
  See [the roadmap](../roadmaps/open/WEBVIEWER_ROADMAP.md) for feasibility, runtime, rendering and security gates.

- **Sound and Mouse Properties use dedicated classic desktop icons at 16x16 and 32x32.**

- **Task Manager opens with a narrower, 560-pixel content area.**

- **Title bars leave a two-pixel gap between Maximize and Close, matching Windows 95–2000.**

- **Preinstalled SUN programs live in `/system`; POSIX programs remain in `/bin`.**
  The desktop and shell find both, and upgrades remove the old copies of shipped SUN programs.

- **SavanXP Classic restores the original small cursors as the default, with both resize diagonals.**
  Original pixels and hotspots are preserved in CUR; alternative packs prefer native images up to 32x32.

- **Sound has a clear heading, an audio icon and grouped playback, application and recording controls.**
  The panel retains the desktop's NT-style widgets, palette and volume meters.

- **The Start menu looks like Windows NT 4.0's**: black-to-blue banner with `SavanXP` in the
  caption face and the system edition rotated along it, 16x16 icons on 28px rows, a two-pixel
  raised frame and an etched separator above `Shut Down...`/`Restart...`.

### Removed

- **Wine's cursor pack is no longer included or offered.**
  Normal image updates retire its former files while preserving custom packs and saved preferences.

### Fixed

- **Doom starts on a fresh system, as on the ISO, instead of exiting with `failed to prepare data directories`.**
  A user's Doom no longer tries to create `/games/doom/savegames`; settings and saves stay in `$HOME/doom`.
  `doom-music-smoke` now starts it without that directory.

- **TCP progresses independently of socket consumers and closes reliably after packet loss.**
  SUN/POSIX retain errors (`POLLERR` for `poll`), drain accepted data before FIN and keep TIME_WAIT for 60 seconds.
  `NET_IOC_GET_TCP_LIFETIMES` reports retained close state; see [NETWORKING.md](../net/NETWORKING.md).

- **Dragging the border of a small application window no longer makes it jump to the ordinary minimum size.**
  Windows opened with a smaller size hint, including Xeyes, now grow smoothly from their starting size.

- **Xeyes installation preserves executable permissions, and its visual checks include the desktop cursor and shadow.**
  `linux-xeyes` checks actual inode modes and every defined content pixel, including both pupils.
  The desktop scenario uses an absolute pointer and both Files clicks within the activation interval.

- **Disks can now expose 32 partitions in total instead of 16, with room for 64 block devices instead of 32.**
  Storage detection and Disk Management cover the increased capacity, including partitions on later USB disks.

- **SUN sockets no longer sleep waiting for NIC initialization or ARP resolution.**
  Connect and datagram sends expose pending routes through `sxn_wait_io`, with cancellation,
  retained setup/ARP errors and bounded timeouts; POSIX keeps the shared network core.

- **Command Prompt finds `linux.sxe` when `/system/linux` is a directory.**
  Command lookup skips directories and devices before trying the `.sxe` suffix.

- **The optional Xlib profile stays optional on hosts without an Alpine root, and X11 titles follow later `WM_NAME` changes.**
  Unsupported event selections and invalid property atoms now fail with core X errors.

- **Desktop pointer queries also compile in C++ SDK consumers.**
  The P1 snapshot helper reads volatile fields individually while retaining the same seqlock checks.

- **The system's programs and libraries no longer carry the build machine's directory as a `RUNPATH`**; 38 did, and
  `check_shared_libs` now fails the build if one does. See [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md).

- **The loader resolves a weak reference nothing defines to zero instead of failing the load, and says in words why
  a non-PIE program cannot use libraries (step 11) or why its own image was not registered (step 10).**
  `ldfailtest`, `ldstatictest` and `ldimagetest` cover every failure step; see [SHARED_LIBRARIES.md](../kernel/SHARED_LIBRARIES.md#the-loaders-failure-paths).

- **A SUN program can return from `main`, call `exit` or `abort`, or fail an `assert`, and it ends with that status
  instead of a #GP (status 141).** The runtime ends every process through `sx_process_exit`, which the native runtime defines with
  `sxn_exit`. See [NATIVE_HEAP.md](../userland/NATIVE_HEAP.md).

- **Win32 windows lay out as on Windows XP: fonts report Windows XP's heights (the System font's 16 pixels), a child's
  `WS_BORDER` is drawn, a disabled window's menu bar turns grey, and F1 sends `WM_HELP`.** See
  [WIN32.md](../userland/WIN32.md#user32-and-gdi32).

- **Win32 programs no longer fail to present a large buffer: the guest heap stopped merging free blocks across two
  arenas the host happened to map side by side.** See [WIN32.md](../userland/WIN32.md#what-they-do-and-what-they-refuse).

- **Old CPUs: C1E on halt is switched off on AMD K8 revision F and family 10h (erratum 400), and XD disabled in the
  firmware is switched back on for Intel**, instead of a stalling tick or `cpu: NX/W^X is required`. Both are logged on
  `cpu:` lines. See [REAL_HARDWARE.md](../hardware/REAL_HARDWARE.md#hw-9--timers-on-old-cpus) (HW-9, HW-10).

- **`sxfs::check` (fscheck) no longer reports a healthy directory with more than 32 subdirectories as unreadable**,
  nor the files below the extra ones as orphan inodes. The 32 limit applies to depth, as mounting applies it.

- **Task Manager's One Graph Per CPU shows up to 32 cores instead of the first 8.**
  The per-core graphs wrap into rows and columns when one row would make them too narrow.

- **The tray volume popup lists playing applications on hosts without a supported network card.**
  It read the legacy UDP census, which needs a configured IPv4 address; it now uses audiod's native port.

- **The kernel's own ACPI parser bounds every table length and address it reads from firmware.**
  A table with a wrong checksum is still used and logged as `acpi: XXXX has a wrong checksum, using it anyway`.
  See [KERNEL_SECURITY.md](../kernel/KERNEL_SECURITY.md#acpi-table-walk); `acpi-tables-test` covers it on the host.

- **Only the system can take the display session: `GPU_IOC_ACQUIRE` answers `EPERM` to a user process.**
  `/dev/gpu0` stays open to everyone for queries and 3D contexts.

- **Received IPv4, ICMP, TCP and UDP checksums are verified, and damaged packets and IPv4 fragments are dropped.**
  A TCP handshake only completes from the address it was sent to. `NET_IOC_SET_TCP_FAULT` now requires the system
  and gains `corrupt_rx_every`. See [NETWORKING.md](../net/NETWORKING.md#testing-what-only-a-bad-network-exercises).

- **The loader rejects a PIE (`ET_DYN`) segment whose end wraps the address space** at validation, not at the copy.
  See [KERNEL_SECURITY.md](../kernel/KERNEL_SECURITY.md#third-pass-audit-2026-11-04), E7.

- **A user process can no longer take the port name of a system service or fill the port table.**
  `SXN_SYS_PORT_CREATE` answers `EPERM` for the services' names and anything under `sys.`, and user ports share 8 of
  the 16 slots. See [KERNEL_SECURITY.md](../kernel/KERNEL_SECURITY.md#third-pass-audit-2026-11-04), E3.

- **A power cut during a create, delete or rename on SxFS no longer leaves a file without a name.**
  Directories are copied on change inside the metadata commit (`SXFS_FEATURE_LINK_COUNT`); `fscheck` adds
  `pending_deletions`. See [SXFS_NAMESPACE.md](../fs/SXFS_NAMESPACE.md).

- **TCP reports refused connections as `ECONNREFUSED` and retains connection failures after readiness.**
  Expired `connect` calls stop retransmitting; `smoke native-network` covers success, refusal and timeout.

- **The keyboard layout selector spells `Español` with ñ.**

- **Display Properties keeps a bottom margin below the wallpaper list at square and portrait resolutions.**
  The monitor preview scales to fit the available space while preserving its proportions.

- **The ISO starts SUN services from `/system` with their execute permissions intact.**
  ISO volume rebuilding preserves recorded owners and permissions, and incremental builds refresh `sxfs-cli` when its ownership rules change.

- **Visual desktop smokes accept `--virtio` and use the tablet's absolute pointer.**
  The relative-only taskbar driver keeps its existing restriction.

- **Virtio GPU activates the hardware cursor on its first upload and hides it correctly.**
  Failed cursor uploads fall back to software rendering.

- **Doom and Celeste audio acceptance now checks the installed ports without a network card.**
  `smoke audio-ports-offline` requires both games in Sound and audible recorded PCM;
  old ports with an embedded UDP-only SDK must be rebuilt, preserving their data.

- **Sound's recording replay remains paced independently of window repainting and control refresh.**

- **Azalia can recover a failed controller without reusing DMA buffers that may still be active.**
  Late codec replies require a reset; unavailable codecs stay visible and recording must reopen.
  Safe queued playback is preserved during scheduling delays. See [AZALIA.md](../kernel/AZALIA.md).

- **Rebuilt POSIX audio clients can use the mixer without a network card and retain application levels.**
  They reconnect through the native object port; existing UDP binaries remain supported.

- **Waiting for `sync` no longer holds the kernel for an entire deferred storage queue.**
  Durability failures still reach the caller; kernel byte comparisons process long equal buffers efficiently.

- **Sound's input meter stays visible while microphone samples continue arriving.**

- **Small SUN playback writes no longer exhaust virtio-sound descriptors prematurely.**
  Direct playback collects samples into device periods and flushes the final partial period on close.

- **Native audio mixing and Sound controls work without a network card.**
  `audiod` keeps serving SUN clients when UDP is unavailable; `smoke audio-offline` covers this boot.

- **Doom FM music preserves additive instrument timbres and independent operator envelopes.**
  Tremolo and vibrato follow each operator, and channel volume changes affect sounding notes.

- **`tools/iso_boot_test.py` no longer fails a good boot** by reading the handoff line before it was
  whole, which left out the `root mounted` it checks.
