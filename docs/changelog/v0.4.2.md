# SavanXP 0.4.2

## [0.4.2] - 2026-11-06

### Added

- **Boot options for real hardware**: the ISO menu now waits 3 s and adds **boot log on screen**
  (`verbose`, no splash) and **no USB** (`nousb`). The kernel reads the entry's `cmdline:` and logs
  `boot: options "..."`.

- **xHCI on real hardware**, checked on an AMD machine booting the ISO from a USB stick: low-power
  controllers are woken (`was in D3, waking it`), dead ones skipped (`does not answer`), the firmware
  gets 5 s to release one, and Intel ports are moved from EHCI to xHCI.

- **USB hubs and hot plug**: devices behind USB 2 and USB 3 hubs (`usb-hub:` log line), and devices plugged
  in or pulled out while running; a pulled stick's volumes are released and its block device removed.
  New `storage::forget_disk`, `partition::drop`, smokes `usb-hub-smoke` and `usb-hotplug-smoke`.

- **USB sticks**: Bulk-Only mass storage as block devices `usb0`, `usb1`... (`usb-storage:` log line),
  with model and serial in Disk Management, which mounts them like any FAT disk. `diskmgmt-smoke` now also
  attaches a USB stick (serial `SXUSB0`) and mounts, writes and remounts it.

- **USB keyboards, mice and tablets** (`usb-hid`), next to PS/2 and virtio ones: none silences the
  others, and a keyboard plugged in later works. Smokes `usb-kbd-smoke`, `usb-pointer-smoke` and
  `usb-mouse-smoke` boot without an 8042 (`no_ps2`); smokes get a USB mouse unless they ask for the tablet.

- **USB: xHCI controllers and device enumeration.** At boot every xHCI controller is taken from the
  firmware and started (`xhci:` log line), and the devices on its root ports are addressed and configured
  (`usb: port <n> <vid>:<pid> ...`). No class drivers yet. See `docs/roadmaps/done/USB_ROADMAP.md`.

- **QEMU machines with USB**: `./build.sh run --usb` (or `SAVANXP_USB=ON`) adds a `qemu-xhci` controller
  with a USB keyboard and tablet; smokes can ask for them (`usb`) and for a FAT USB stick (`usb_stick_mib`,
  serial `SXUSB0`). No driver yet: see `docs/roadmaps/done/USB_ROADMAP.md`.

- **System Properties** keeps a short note of thanks behind its logo.

- **Disk Management mounts FAT volumes**, owned by the person who mounts them (`fs::Owner`,
  `fs::Driver::adopt_owner`). New host tool `fat-image` (`create`, `put`) builds FAT images with the
  kernel's FatFs; smokes can attach one (`fat_disk_mib`, serial `SXFAT0`).

- **A FAT driver, and the boot volume at `/boot`**: FAT12/16/32 with long names on FatFs
  (`fat::driver()`), read and write. At boot the first FAT volume holding `boot/kernel.elf`, ESPs first,
  is mounted at `/boot` (`storage: /boot is <device>`), writable by the system only, never unmounted.
  New host test `fat-volume-test`. See `docs/roadmaps/open/FAT_ROADMAP.md`.

- **Disk Management** (`/bin/diskmgmt`, a SUN program under System): the volumes as a list and every
  disk as a map of its partitions and free space, with Properties (model, serial, GUIDs, usage).
  Initialize Disk (GPT), New Partition, Format (SxFS), Delete Partition, and Mount/Unmount under `/mnt`
  run elevated, never on the ESP, the disk holding `/` or an MBR disk. New calls `SXN_SYS_STORAGE_*`
  (SNAPSHOT, READ, WRITE, RESCAN, MOUNT, UNMOUNT); volumes can now be unmounted (`fs::release`). Smokes
  can attach a blank disk (`extra_disk_mib`). See `docs/userland/DISK_MANAGEMENT.md`.

- **Files: Explorer toolbar and address bar**: Back, Forward, Up, Delete, Properties and Views,
  an editable address bar, a Go menu and a Properties dialog (Alt+Left/Right, Alt+Enter). SXGUI
  gains `sxgui_toolbar_button` (`SXGUI_FLAG_TOOLBAR`, `SXGUI_FLAG_DROPDOWN`) and `sxgui_separator`.

- **Files: Large Icons view**, now the default, next to Details (View menu, remembered in
  `filesapp.cfg`), without the ".." entry. Folders open with nothing selected and a click on
  the background clears the selection. SXGUI gains the `SXGUI_ICONVIEW` widget (`sxgui_iconview`,
  `sxgui_iconview_item_rect`), `SXGUI_FLAG_EMPTY_SELECTION` and `mime_icon_large`. See
  `docs/desktop/FILES.md`.

- **Display Properties** (`/bin/display`, fixed size), opened from the desktop's Properties or Program
  Manager's Options: any BMP as wallpaper, Center/Tile/Stretch and a colour (`desktop.cfg`, wallpapers in
  `/wallpapers` from `tools/gen_wallpapers.py`; replaces Change Wallpaper). The Settings tab changes the
  resolution live with a 15-second "Keep these settings?" and saves it in `display.cfg`
  (`SAVANXP_WM_WINDOW_ACTION_SET_DISPLAY_MODE`, `gfx_set_display_mode`, `sxgui_trackbar`). See
  `docs/desktop/DISPLAY_PROPERTIES.md`.

- **Desktop icons and shortcuts**: the desktop shows `/users/<name>/Desktop` as a grid of icons
  (created with Command Prompt, Files and Notepad). Double click opens, drag moves, F2 renames, Delete
  asks first; right click opens the background's menu (Arrange Icons, Refresh, New Folder, New Text
  Document, Properties) or the icon's (Open, Rename, Delete). Shortcuts are `.sxlnk` text files
  (`target=`, `args=`, `workdir=`, `icon=`). See `docs/desktop/DESKTOP_ICONS.md`.

- **Context menus in applications**: an application may open a popup owned by its window
  (`SAVANXP_WM_WINDOW_ROLE_POPUP`), and SXGUI shows one with `sxgui_context_menu_open` (also
  `sxgui_popup_menu_*`, `sxgui_listbox_row_at`; SUN: `sxnwm_popup_open`). Files gets Open, Send To
  Desktop, Rename... and Delete on a right click, Shift+F10 or the Menu key, and opens a folder given
  as its argument; Task Manager gets End Process (Tree) and Switch To / End Task on its rows.

- **The kernel lock reports its contention**: `smp-stats:` lines next to `timer-stats:`, per entry
  point (syscall, timer, irq, ...), with the longest hold and the syscall behind it. See
  `docs/roadmaps/open/SMP_ROADMAP.md#reading-smp-stats`.

- **Task Manager: Applications tab** (End Task, Switch To, New Task). Any WM client can read the
  task list and switch to or close a task (`SAVANXP_WM_WINDOW_ACTION_TASK_LIST`/`_ACTIVATE`/`_CLOSE`,
  `sxnwm_task_*`); closing takes the same user or the system. See `docs/userland/SYSTEM_MONITORING.md`.

- **Task Manager: one CPU graph per core and kernel times** (View → CPU History, Show Kernel
  Times, red under the total); Totals gains Threads. `tools/shoot.sh --smp N` boots more cores.

- **Task Manager: User Name, CPU Time and Threads columns, sort by header, End Process Tree**
  (elevates once for the rest of the tree). SXGUI list headers can be clicked
  (`SXGUI_COLUMN_CLICKABLE`, `SXGUI_ACTION_HEADER`, `sxgui_header_column`).

- **SUN programs can use the SXGUI toolkit** through `sxn/sxngui.h` (`sxngui_app_init`,
  `sxngui_app_run`), with dialogs in owned windows (`sxnwm_window_open`, `sxnwm_poll_owned_input`)
  and `sxnwm_set_cursor_shape`. See `docs/desktop/PLATFORM_GRAPHICS.md`.

- **SUN programs can read the process table and the system** (`SXN_SYS_PROCESS_SNAPSHOT`,
  `SXN_SYS_SYSTEM_INFO`, `sxn_process_snapshot`, `sxn_system_info`) and ask for elevation
  (`sxn_elevate` in `sxn/sxnelevate.h`). `savanxp_process_info` gains `kernel_ticks`,
  `thread_count` and `uid`; POSIX `proc_info` keeps the old size. See slice 27 in
  `docs/kernel/KERNEL_NATIVE_API.md`.

- **SxFS records an owner, a group and a mode on every inode** (`SXFS_FEATURE_OWNERSHIP`, no format
  version bump). An existing image is stamped with the default of each path by the build or on its
  first mount; nothing enforces them yet. `fscheck` reports `ownership_recorded` and
  `unowned_inodes`; `sxfs-cli extract` and `apply` carry ownership (`owner` lines) through a
  compaction. See `docs/kernel/USERS_AND_PERMISSIONS.md`.

- **Every process carries an identity, and the VFS checks it** on every path operation; everything
  still runs as the system. `setuid`/`seteuid`/`setgid` only lower, `chmod`/`fchmod`/`chown`/
  `access` work, `umask` applies, and `stat` reports owner, mode and `st_mtime` (new `STAT_EX`,
  `FSTAT_EX`, `OPEN_MODE`, `MKDIR_MODE`). `/dev/input0` and `/dev/mouse0` are 0600. New `idtest`
  in the core smoke. See `docs/kernel/USERS_AND_PERMISSIONS.md`.

- **Elevation: a program can run with the system's rights once the user says yes** on a prompt
  windowd draws above every window, answered only by the keyboard and mouse it reads. New broker
  `elevationd` (init starts it), `elevate()` in the libc, `INPUT_IOC_CLAIM` (windowd is the only
  reader of `/dev/input0` and `/dev/mouse0`), `SXN_SYS_PORT_CONNECT_EX`/`_ACCEPT_EX` and
  `SXN_SPAWN_FLAG_IDENTITY`. New `elevation-smoke` answers it with real keys over QMP. See
  `docs/kernel/USERS_AND_PERMISSIONS.md#elevation`.

- **SxGL, the 3D rasterizer: a documented OpenGL 1.1 fixed-function subset in software**
  (`sxgfx/sxgl.h`), beside SxGFX and linkable from POSIX and SUN programs alike. Clipping, top-left
  fill rule, lighting, perspective-correct textures, fog, alpha test, blending and scissor; the
  program presents what `sxgl_swap_buffers` reports. New host test `sxgl-test` with a
  triangles-per-second benchmark. See `docs/desktop/SXGL.md`.

- **Nightwood, the first game written against SUN** (`/bin/nightwood.sxe`, Games): a forest at
  night drawn with SxGL, eight photographs to find and something that follows, with mouse look and
  synthesized sound. New `nightwood-smoke` (`nightwood --selftest`) and
  `tools/shoot.sh --scenario nightwood`. See `docs/userland/NIGHTWOOD.md`.

- **SUN programs can play sound** (`sxn/sxnaudio.h`): `audiod` also listens on the native port
  `audiod`, and a SUN stream reaches it there, or writes `/dev/audio0` directly when no daemon runs.
  The wire protocol moved to `audio/audiod_protocol.h`. See `docs/media/AUDIO_DAEMON.md#sun-clients`.

- **A window can capture the pointer** (`sxnwm_set_pointer_capture`): while it is the active window
  the cursor hides and it gets relative `SAVANXP_WM_EVENT_POINTER_MOTION`; losing the focus suspends
  the capture. See `docs/desktop/WM_SUBSYSTEM.md#pointer-capture`.

- **`SAVANXP_QEMU_DISPLAY=sdl` opens QEMU with SDL instead of GTK**, whose grab cannot confine the
  host pointer on Wayland; with SDL a captured pointer stays in the window. See
  `docs/build/BUILD_LINUX.md#the-qemu-window`.

### Changed

- **The user's settings live in `/users/user/Settings`** instead of loose in the profile:
  `savanxp_settings_path` makes the folder and moves an older loose `.cfg`/`.ini` in on first use;
  the system's stay at the root. See `docs/kernel/USERS_AND_PERMISSIONS.md`.

- **The development boot drive is attached as `fat:<dir>,snapshot=on`** (`tools/run_qemu.py`): the guest
  can write `/boot`, and its writes are discarded at exit instead of reaching `build/image`.

- **Only a driver marked `can_be_root` mounts `/`** (`fs::Driver::can_be_root`; SxFS is): a FAT boot
  drive ahead of the system disk can never become the root. FatFs R0.16 is vendored under
  `vendor/fatfs/`. See `docs/roadmaps/open/FAT_ROADMAP.md`.

- **GPT tables are checked before they are used**: both CRCs, falling back to the backup header
  (`partition: <disk>: primary GPT damaged, using the backup`); a disk with neither is left whole. The
  AHCI and ATA boot lines show each disk's model and serial.

- **The version shows the build number**, `0.4.2 (Build 588)` (the commit count): boot screen,
  kernel log, desktop stamp, About, the console banner and a new `build` line in `sysinfo`. Master now carries the
  next version (0.4.2); the build warns if `version.h` names an already tagged release.

- **The Start menu opens without the one-second wait**: it keeps the catalog and rebuilds it only
  when `progman_registry_disk_signature()` changes, and a rebuild opens each binary once. The SDK
  gains `struct sxe_file` (`sxe_file_open`, `sxe_file_read_section`, `sxe_file_load_meta`,
  `sxe_file_load_icons`), which reads the ELF's section table in one go. See
  `docs/userland/SXE_FORMAT.md`.

- **Smokes and `tools/shoot.sh` boot at the default resolution** whatever the developer chose in
  Display Properties: `tools/smoke_profile.py` removes `display.cfg` from the disposable copy, so a
  `build/disk.img` at 1024x768 no longer fails `taskbar-smoke` or the visual scenarios.

- **Clicking the desktop gives it the keyboard**: `windowd` has a desktop focus state, so the icons
  get arrows, Enter, Delete and F2. A right press activates the window it lands on and closes
  popups, as a left press does.

- **A kernel panic or ring-0 fault stops every core** by NMI and says so (`smp: other cores stopped
  (n/n)`). `POWER_IOC_PANIC` on `/dev/power` (system only) and `panic-smoke` exercise it.

- **Device interrupts go to the APs** once they schedule (`ioapic: GSI n (vector v) -> lapic m`);
  the BSP keeps the tick's work, MSI-X stays on it. uACPI gets real spinlocks, mutexes and events.

- **QEMU boots two cores by default** (`build.sh`, `tools/run_qemu.py`, `tools/run_smoke.py`,
  `tools/shoot.sh`, `SAVANXP_SMP`), smokes included; `--smp 1` keeps one. See
  `docs/roadmaps/open/SMP_ROADMAP.md#two-cores-by-default`.

- **Task Manager is a SUN program**, `/bin/taskmgr.sxe`, built from `system/taskmgr`; the POSIX
  `/bin/taskmgr` is removed from the image. It looks and behaves as before, and its idle window no
  longer wakes up between refreshes.

- **`SXN_SYS_TERMINATE` follows kill's rule**: a descendant, a process of the caller's uid, or any
  when the caller acts as the system; otherwise `-EPERM` (was `-ECHILD`). Idle and init are
  `-EACCES`, the caller itself `-EINVAL`.

- **The taskbar looks like Windows NT 4.0's.** Two-pixel button bevels (24 px high), a dithered bold button for the
  active window, and one sunken tray well holding the layout, speaker and clock as flat cells.

- **Gears draws with SxGL** instead of its own rasterizer: geometry crossing the near plane is
  clipped, and shared edges are no longer drawn twice.

- **The elevation prompt shows every argument** of the program it would run, escaped and quoted
  so what is drawn is what runs, and grows to fit them; a request that does not fit on the screen
  fails with `E2BIG` instead of being cut off. See `docs/kernel/USERS_AND_PERMISSIONS.md#elevation`.

- **The desktop runs as the user** (uid 1000), and so does everything started from it; windowd and
  compositord stay the system's. `SAVANXP_PROC_FLAG_SYSTEM` reports which processes act as the
  system. See `docs/kernel/USERS_AND_PERMISSIONS.md`.

- **Add or Remove Programs asks for elevation** to uninstall when run by the user, through
  `appwiz --uninstall`.

- **Settings live in the user's profile**, `/users/user`, which init makes at boot: `progman.ini`,
  `desktop.cfg`, `mines.ini`, `assoc.ini`, `audio.cfg`, `keyboard.cfg`... are found with
  `savanxp_settings_path` (`HOME` says the same), falling back once to the old copy at the root. Doom
  saves in `$HOME/doom`. New `/dev/keyboard` for the layout; `kill` of another person's process and
  setting the clock are `EPERM` for the user. See `docs/kernel/USERS_AND_PERMISSIONS.md`.

- **The system runs from its disk, mounted at `/`**: `/bin`, `/lib` and `/games` are the SxFS
  volume's, and the initramfs moved to `/rescue`, where init starts from when no disk mounts.
  `PATH` is `/bin:/rescue/bin`; the loader and `--dynamic-linker` use `/lib`. `/disk/...` stays as
  an alias of `/`, so binaries already installed keep working. The boot log reads `root mounted`.
  See `docs/kernel/FILESYSTEMS.md`.

- **The initramfs is a rescue system** (8.4 MB, from 45 MB): with no disk, init keeps
  `/rescue/bin/sh` on the text console. New `rescue-smoke` boots with no disk (`--no-disk`).
  Add or Remove Programs subtracts the build's `/system/programs.txt`.

- **The kernel is written against `namespace arch`** (`arch/cpu.hpp`, implemented by `arch/x86_64`),
  and x86 code lives only under `arch/` and `include/arch/`: drivers share one port I/O header
  (`arch/x86/io.hpp`) and call named CPU operations (`arch::memory_barrier`, `arch::cpu_relax`,
  `arch::load_page_table_root`, ...) instead of inline assembly. See `docs/kernel/ARCH.md`.

- **The userland runtime's units are listed once**, in `subsystems/posix/sdk/v1/runtime/units.txt`;
  CMake, `tools/build-user.sh` and the Doom, ccleste and FFmpeg ports read it
  (`tools/lib/runtime_units.sh`). See `docs/build/BUILD_CMAKE.md`.

- **SXGFX, SXCHROME and SXGUI-C left the POSIX SDK for the platform layer** (`system/gfx`,
  `include/sxgfx`), with the pixel primitives and fonts split out of the POSIX window client. The
  toolkit takes clipboard and clock from a `struct sxgui_host` (`sxgui_set_host`); POSIX programs
  get theirs automatically. `savanxp/gfx2d.h`, `sxchrome.h` and `sxgui.h` keep working for POSIX
  code. Out-of-tree builds compile `system/gfx/*.c`. See `docs/desktop/PLATFORM_GRAPHICS.md`.

- **The WM protocol headers moved to `include/wm/`** (`wm/wm_protocol.h`, `wm/wm_shell_protocol.h`), so
  SUN's `sxnwm.h` and the native services no longer include the POSIX SDK. `savanxp/wm_protocol.h` and
  `savanxp/wm_shell_protocol.h` forward to them. See `docs/desktop/PLATFORM_GRAPHICS.md`.

- **The VFS reaches filesystems only through `fs::Driver`**, which now carries the file, path and
  volume operations; `sxfs` is one registered driver and `vfs.cpp` no longer names it. No mount point
  can be removed or renamed, not just `/disk`; `sync` flushes every mounted volume. ATA's polling
  diagnostics log in English via `block::report_health`. See `docs/kernel/FILESYSTEMS.md`.

- **Input drivers register with the kernel's input layer** (`input::register_driver`), and the
  keyboard logic (modifiers, locks, ES/EN layouts) is shared instead of living in the PS/2 driver.
  virtio-input no longer poses as PS/2, and `input_ready` is true with any keyboard. `kbd-smoke` also
  checks Caps Lock and AltGr. See `docs/kernel/INPUT.md`.

- **SUN programs are named `<name>.sxe` on disk** (`/bin/console.sxe`, `/bin/windowd.sxe`), and the
  shell finds them without the extension. `tools/stamp_osabi.py` refuses a native image without `.sxe`
  or `.sxmeta`, and `build-user.sh --native` installs `NAME.sxe`. Installing a program retires its other
  name in `/disk/bin` (`sxfs-cli rm -f`). See `docs/userland/SXE_FORMAT.md`.

### Fixed

- **Booting without a PS/2 controller hung** in `ps2` initialization; it now logs `ps2: no 8042 controller`.

- **A FAT volume over a whole disk is no longer read as an MBR**: its boot sector ends in `0x55AA` too,
  and `partition::` sliced its boot code as a table. Such a disk now has no scheme and mounts whole.

- **Asking for a volume's usage no longer stalls the system**: SxFS counted its used sectors one bit at a
  time, a third of a second under the kernel lock on a 1 GiB volume, each time Task Manager, `sysinfo` or
  `df` asked; mouse input was lost meanwhile. It now counts 64 bits at a time (about 100 times faster).

- **POSIX `open` with no access mode returns `EINVAL`** instead of a read handle that skipped the
  permission check (a `0600` file or an unreadable directory could be read). The kernel keeps it as a
  query open ([`KERNEL_SECURITY.md`](../kernel/KERNEL_SECURITY.md#third-pass-audit-2026-11-04), E1).

- **A port can no longer be sent over a pipe** (`PIPE_SEND_HANDLE` returns `EINVAL`): queued on its
  own pending connection it kept itself, its name and one of the 16 port slots until reboot (E2).

- **A program started by name from the Command Prompt shows its own title and icon** (`Calculator`,
  not `calc` with the generic icon): the window runtime finds a bare `argv[0]` in `/bin` and
  `/rescue/bin`. The `taskbar` scenario of `tools/shoot.sh` follows the NT 4 taskbar's geometry again.

- **The APs start on processors without SMEP** (QEMU `-cpu qemu64`): since v0.4.0 they halted at
  start-up and the system ran on one core.

- **Four cores under QEMU TCG no longer crawl**: the kernel lock spins without `pause` there
  (`cpu: QEMU TCG, the kernel lock spins without pause`); `smoke --smp 4` passes instead of timing out.

- **Task Manager's End Process works on processes that are not the user's**: it asks for elevation
  and the elevated `taskmgr --end <pid>` ends them; a refusal shows "Unable to Terminate Process"
  instead of failing silently. `elevation-smoke` covers it.

- **A held key no longer answers the elevation prompt**: the keyboard core marks repeats with the new
  `SAVANXP_KEY_MOD_REPEAT` bit, and the prompt ignores them.

- **Add or Remove Programs refuses a `data_dir` under `/users`**, so uninstalling a program cannot
  delete the profiles; and `compositord` takes as its window manager only a system process.

- **`elevation-smoke` runs from a clean checkout**: `tools/qmp_elevation.py`, which answers its
  prompts, was never tracked.

- `ports/ffmpeg/runtime.sh` builds again: it still compiled SXGFX and SXGUI-C from the POSIX runtime
  directory they left for `system/gfx`.

- **`taskbar-smoke` passes again.** It compares the muted speaker with its icon file instead of a colour
  from before the Windows 2000 icon redraw, and `--virtio` is refused up front: the smoke needs a
  relative pointer.

- **CMake uses the `python3` on `PATH`**, so a versioned interpreter earlier in `PATH` without Pillow
  (uv, pyenv) no longer breaks a fresh configure or `tools/verify_doom_persistence.sh`. Override with
  `-DPython3_EXECUTABLE`.
