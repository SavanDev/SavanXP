# Intel Core i5-4440 (MSI MS-7817, H81)

A Haswell desktop on an MSI board with the H81 chipset, using the
processor's HD Graphics 4600. It runs `master`, and is the first Intel desktop
and the second UEFI machine to boot it. The shared contract and the numbered
work packages (HW-n) are in [REAL_HARDWARE.md](REAL_HARDWARE.md).

## Status

| When | What |
| --- | --- |
| **Verified**, 2026-11-13 | SavanXP v0.4.3 (Build 701) booted from a USB stick under **UEFI** and ran for about 7 minutes. Desktop at 1920x1080 from GOP; a **low-speed** USB keyboard and mouse on xHCI; the stick read and a partition mounted through Disk Management; a SATA SSD found by AHCI and its partitions read; Doom, Celeste, Nightwood, the media player and `sxgldiag` all ran |
| Not working | Ethernet (HW-1) |
| Not run | Audio output: the machine had no speakers, so the ALC887 attached but nothing was heard. Writing the SSD, the legacy BIOS path |

The log is the only record of the run; no Linux inventory was taken.

## The unit

Read from the boot log (`system-log-i5-4ta.txt`, not in the tree).

| Item | Seen on the unit |
| --- | --- |
| Processor | `GenuineIntel family 0x6 model 0x3c stepping 3`, i5-4440 @ 3.10GHz, 4 cores |
| Memory | 7541 MiB usable |
| Board | MSI MS-7817 (PCI subsystem `1462:7817`), H81 (`8086:8c5c`) |
| Graphics | HD Graphics 4600 (`8086:0412`), with its HDMI audio function (`8086:0c0c`) |
| SATA | `8086:8c02`, AHCI mode. `ADATA SU650`, a 120 GB SSD |
| USB | xHCI `8086:8c31`, two EHCI (`8086:8c2d`, `8c26`), each behind an Intel rate-matching hub |
| Audio | PCH HD Audio `8086:8c20`, Realtek ALC887 (`0x10ec0887`) |
| Ethernet | Realtek RTL8111/8168, `10ec:8168` rev 0c |

14 functions; the `_PRT` link devices all report their GSI, unlike the AMD
boards.

## What the log shows

### Processor and timers

```
boot: firmware UEFI 64, loader Limine 10.8.5
cpu: features lm nx sse2 sse3 ssse3 sse4.1 sse4.2 cx16 lahf_lm popcnt avx apic x2apic rdrand smep invtsc pdpe1gb
timer: PM timer ACPI de 24 bits (0x1808), el reloj de pared sigue en el TSC
cpu: APIC local en modo x2APIC (id 0)
timer: local APIC calibrated divisor=6249 target_hz=1000
smp: 4 cores reportados, 4 en linea (bsp lapic 0, x2APIC)
```

- Every hard requirement is met. SMEP on; Haswell has no SMAP.
- Under UEFI the `smp:` line agrees with `cpu:` and says x2APIC. On the
  Compaq's legacy boot it did not; that mismatch is a legacy-path matter.
- The PM timer is 24 bits, so the wall clock is the invariant TSC.
- The APIC timer calibrated to 100 MHz (`divisor=6249` at 1000 Hz with
  divide-by-16), Haswell's actual bus clock.
- **`timer-stats:` loses time all the time**: 194 of 195 windows lost at
  least 1%, most of them 7%, idle included, with the handler at 3 µs. The
  A6-3500 shows the same pattern with a different wall clock. See
  [HW-9](REAL_HARDWARE.md#hw-9--timers-on-old-cpus).

### Devices

| Device | Log | Result |
| --- | --- | --- |
| Display | `fb_gpu: 1920x1080 nativo, 8100 KiB mapeados (tipo del firmware)` | **Verified.** GOP gave the monitor's preferred mode |
| USB | `xhci: 0:14.0 8086:8c31, 17 ports, 32 slots, 32-byte contexts` | **Verified.** A low-speed keyboard (`258a:1`) and mouse (`46d:c077`) and the stick on xHCI. Both EHCI controllers reported `0 companions` and came up with their rate-matching hubs (`usb-hub: 4 ports on 8087:8008`, `6 ports on 8087:8000`): the first USB hubs seen on metal. Nothing was plugged behind them |
| SATA | `ahci: ahci0 port 1, 234441648 sectors, "ADATA SU650"` | **Verified.** Its three partitions were read |
| Audio | `azalia: ready 0:1b.0 codec=0x10ec0887 address=0 pin=0x14 dac=0x2` | Attached, capture found. **Not heard**: no speakers. The HDMI controller came first: `azalia: codec 0 probe failed (5)`, then skipped |
| PS/2 | `ps2: keyboard reset failed` | Nothing on the PS/2 port, as expected |
| Ethernet | `nic: ningun driver reclamo el hardware` | No network (HW-1) |

**`azalia: late writer`** appeared 27 times in 7 minutes, against none or one
on the other machines. The producer fell behind the DMA position about every
10 seconds while something played. With no speakers nothing was heard; on a
machine with them it would be a click each time.

### Performance

At 1920x1080, all drawing in software:

| Workload | Result |
| --- | --- |
| Compositor | Median 32 fps across the run, up to 183 fps with small damage |
| Doom (`doomgeneric`) | Median 36 fps, 69 at most, in 122 reports |
| `sxgldiag` software backend | 774 frames in 5 s, 155 fps, 3125 triangles |
| `audiod` | `dropped=0 mismatch=0` with up to two streams |

`windowd: mediaplayer (pid 22) is not responding` appeared once, about two
minutes after the player started. Whether it recovered is not recorded.

## Work for this target

1. **The steady tick loss** (HW-9). This is the machine to chase it on:
   modern, UEFI, x2APIC, invariant TSC, and still 7% lost at idle.
2. **The late writers**: with speakers connected, check whether they are
   heard, and what `audiod` was doing at the time.
3. **HW-1**, the same `10ec:8168` as the development host.
4. A device behind the EHCI hubs, to run split transactions on metal.
