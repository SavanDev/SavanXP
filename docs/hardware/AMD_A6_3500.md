# AMD A6-3500 + GeForce GT 610 (Gigabyte A75)

A Llano desktop: the first APU generation, on a Gigabyte board with the A75
fusion controller hub, and a discrete NVIDIA card in place of the APU's own
graphics. It runs `master`. The shared contract and the numbered work packages
(HW-n) are in [REAL_HARDWARE.md](REAL_HARDWARE.md).

## Status

| When | What |
| --- | --- |
| **Verified**, 2026-11-13 | SavanXP v0.4.3 (Build 701) booted from a USB stick through the firmware's **legacy BIOS path** and ran for about 10 minutes. Desktop at 1024x768; a **low-speed** USB keyboard and mouse through EHCI's OHCI companions; the stick read and a partition mounted through Disk Management; Doom, Celeste, Nightwood, the media player and `sxgldiag` all ran |
| Not working | The SATA disks: the controller is in native IDE mode and `ata.cpp` reaches only legacy ports (HW-3). Ethernet (HW-1) |
| Not run | Audio output: the machine had no speakers, so the ALC887 attached but nothing was heard. UEFI |

The log is the only record of the run; no Linux inventory was taken.

## What the log shows

### Processor and timers

```
cpu: features lm nx sse2 sse3 sse4a cx16 lahf_lm popcnt apic invtsc pdpe1gb
cpu: SMEP unavailable on this processor
timer: reloj de pared por PM timer ACPI (0x808, 32 bits)
timer: local APIC calibrated divisor=12469 target_hz=1000
smp: 3 cores reportados, 3 en linea (bsp lapic 0, xAPIC)
```

- Every hard requirement is met; SMEP and SMAP are absent, so neither is on.
  No `x2apic` and no `rdrand`: the xAPIC MMIO path and the TSC-mixed entropy
  fallback both ran on metal.
- The wall clock is the 32-bit PM timer.
- Family 12h is outside the erratum 400 range the kernel checks, so no `C1E`
  line appears; Linux treats family 12h and later as keeping the APIC timer
  running in deep C-states.
- **`timer-stats:` loses time all the time**: 255 of 256 windows lost at
  least 1%, most of them 7%, idle included, with the handler at 30 µs. See
  [the steady loss](REAL_HARDWARE.md#hw-9--timers-on-old-cpus) in HW-9; the
  i5-4440 shows the same pattern and the FX-4100 does not.

### PCI and devices

27 functions. The `_PRT` link devices report no IRQ in `_CRS`, as on the
Ryzen host; routing worked through the entries that name a GSI.

| Device | Log | Result |
| --- | --- | --- |
| Display | `fb_gpu: 1024x768 nativo, 3072 KiB mapeados (tipo del firmware)` | **Verified** at 1024x768. The GT 610's video BIOS offered that as the preferred mode; whether the monitor's native mode was higher is not recorded (HW-11) |
| USB | `ehci: 0:12.2 1022:7808, 5 ports, 1 companions` ×3, `ohci:` ×4 | **Verified.** The first run of EHCI and OHCI on metal: `ehci: port 4: low-speed device, handed to the companion`, then `usb: ohci1 port 4 413c:2003 ... low-speed "Dell USB Keyboard"` and a low-speed mouse. The stick at high speed on EHCI. An SD card reader with no card answered nothing |
| SATA | No `ata:` or `ahci:` disk line | **Not reached.** The controller is in native IDE mode, so its channels are at the BARs, not at `0x1F0`/`0x170`. Switching the firmware to AHCI should find the disks with the existing driver; HW-3 is the fix that needs no firmware change |
| Audio | `azalia: ready 0:14.2 codec=0x10ec0887 address=0 pin=0x14 dac=0x2` | Attached, capture found (`pin=0x18 adc=0x8`). **Not heard**: no speakers. The GT 610's HDMI function was skipped as having no analog path |
| PS/2 | `ps2: keyboard reset failed` | Nothing on the PS/2 port, as expected |
| Ethernet | `nic: ningun driver reclamo el hardware` | No network (HW-1) |

### Performance

At 1024x768, all drawing in software:

| Workload | Result |
| --- | --- |
| Compositor | Median 26 fps across the run, up to 360 fps with small damage |
| Doom (`doomgeneric`) | Median 19 fps, 65 at most, in 77 reports |
| `sxgldiag` software backend | 436 frames in 5 s, 87 fps, 1802 triangles |
| `audiod` | `dropped=0 mismatch=0`; the media player's two streams counted tens of thousands of underruns, so the player fed the mixer late |

`windowd: mediaplayer (pid 18) is not responding` appeared once, three minutes
after the player started. Whether it recovered is not recorded.

## Work for this target

1. **SATA in AHCI mode** in the firmware, to see the disks today. Then HW-3,
   so IDE mode works too.
2. **The steady tick loss** (HW-9): find out whether it is a lost interrupt
   or a ruler that is wrong, on this machine or the i5-4440.
3. **HW-1**, the same `10ec:8168` as most other targets.
4. **Audio** with speakers on the jack, recorded as the ALC892 and ALC269
   were.
5. **The resolution**: whether the monitor's native mode is listed by the
   GT 610's VBE BIOS, and through the *SavanXP (1024x768)* entry otherwise.
