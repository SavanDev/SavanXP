# Web Viewer's engine libraries

NetSurf's MIT libraries are vendored, built and proven here. They read HTML
into a DOM and compute CSS styles; Web Viewer's own layout, paint and,
later, scripting go on top. This is stage E1 of
[WEBVIEWER_ROADMAP.md](../roadmaps/open/WEBVIEWER_ROADMAP.md#e1--the-libraries-build).
Since E2, Web Viewer walks the document libhubbub and libdom produce. E3
uses libcss computed styles in the paragraph renderer.

## What is vendored

| Library | Release | What it does |
|---|---|---|
| libparserutils | 0.2.5 | input streams and charset codecs (ASCII, ISO-8859-x, Windows-125x, UTF-8, UTF-16), with no `iconv` |
| libwapcaplet | 0.4.3 | interned, reference-counted strings |
| libhubbub | 0.3.8 | the HTML5 tokeniser and tree builder |
| libdom | 0.4.2 | the DOM, with its hubbub binding (not the XML one) |
| libcss | 0.9.2 | the CSS parser, the cascade and computed styles |

Each one sits under `vendor/netsurf/<name>/`, unmodified:
- **Source:** the release tarball, without its `test/` directory, which is
  25 MiB of conformance data that nothing here runs. libhubbub's `perf/` and
  the `.github/` directories are also left out.
- **Pin:** `vendor/netsurf/NETSURF_RELEASES.txt` records each tarball's
  SHA-256. NetSurf publishes no checksums, so the hashes are of the archives
  as downloaded from `download.netsurf-browser.org` on 2026-11-22.
- **Registry:**
  [THIRD_PARTY_PROVENANCE.md](../third-party/THIRD_PARTY_PROVENANCE.md#netsurf-libraries)
  holds the entry.

All five are MIT. NetSurf's core is GPL-2.0-only, and Web Viewer neither
takes nor reads it ([the clean-room
rule](../roadmaps/open/WEBVIEWER_ROADMAP.md#the-clean-room-rule)). The glue
below is written from the libraries' own headers and `docs/`.

## The build

`cmake/NetSurf.cmake` builds every library twice from the same sources, as
static archives:
- **`netsurf_<name>`** is for SUN programs. It uses the user target's PIC
  flags, for PIE programs, and the SDK's C headers.
- **`netsurf_<name>_host`** is for the host tests.

Each archive names the ones it needs, so a program links `netsurf_css` and
`netsurf_dom` and gets the rest. The SUN archives ask only for what both C
runtimes define (below), so a POSIX program can link the same archives. None
does yet.

The flags are upstream's release build: C99, `_BSD_SOURCE`,
`_DEFAULT_SOURCE`, `WITHOUT_ICONV_FILTER` and `NDEBUG`. Without `NDEBUG`,
hubbub's tokeniser and tree builder print every state they enter. There is
also `_ALIGNED=__attribute__((aligned))`, which NetSurf's shared makefiles
define and which is not vendored. Left undefined, `struct css_rule {...}
_ALIGNED;` declares a variable in every file, and only the link notices.

The SUN archives carry line tables only (`-gline-tables-only`), not full
debug information. A program that links them is about 3 MB on disk instead
of 7.

### What upstream generates

The build generates these files into `build/.../netsurf-generated/`, once,
for both flavours:

| File | From | Tool |
|---|---|---|
| libparserutils `aliases.inc` | `build/Aliases` | Perl, `make-aliases.pl` |
| libhubbub `entities.inc` | `build/Entities` | Perl, `make-entities.pl` |
| libhubbub `autogenerated-element-type.c` | `element-type.gperf` | gperf, then its table is made `static`, as upstream does with sed (`cmake/NetSurfStatic.cmake`) |
| libcss `autogenerated_<property>.c`, about 120 of them | `properties.gen`, one line each | `css_property_parser_gen.c`, a host program built and run by CMake |

The Perl scripts write to paths relative to the directory they run in. Each
one runs in a generated directory that holds a copy of its table. Perl was
already needed for the OpenSSL port. gperf is new to the build, and both are
found through `find_program` (`SAVANXP_PERL`, `SAVANXP_GPERF`).

### What the libraries may ask the program for

`tools/check_archive_symbols.py` runs after the SUN archives are built
(target `netsurf_symbols`). It fails the build when they ask the program for
anything outside this list: `abs bsearch calloc free malloc memcmp memcpy
memmove memset realloc snprintf __stack_chk_fail __stack_chk_guard strdup
strlen strncasecmp strncmp strncpy strtol strtoul time tolower`.

Each of these is a C function that SUN's runtime answers without a POSIX call.
`time()` goes through the native clock hook
([NATIVE_HEAP.md](../userland/NATIVE_HEAP.md)). A file, stdio or a thread
would be a POSIX call inside a SUN program. This is the same rule
`ports/openssl/link.sh` applies to OpenSSL, and a program that links the
archives depends on the check.

The libraries needed one thing from the SDK: libcss calls `strncasecmp` with
only `<string.h>` included, as glibc and musl allow. The SDK's `<string.h>`
now includes `<strings.h>` when `_DEFAULT_SOURCE`, `_BSD_SOURCE` or
`_GNU_SOURCE` is defined.

## The glue (`system/webview/engine/`)

`webengine.h` is the engine's contract. It is neutral: it needs only the C
library, so the same source builds into SUN programs and the host test.

- **`webengine_parse_html`** parses a whole document through the hubbub
  binding. When a `<meta charset>` changes the encoding partway through, the
  parse starts again once in that encoding, as HTML's "change the encoding"
  step does. Unlabelled documents with valid non-ASCII UTF-8 keep their UTF-8
  text.
- **`webengine_stylesheet`** turns one piece of CSS text into a sheet, either
  an author sheet or the body of a `style=""` attribute. Resource values and
  `@import` do not initiate fetches.
- **`webengine_visit_sheets`** enumerates `<style>` and eligible stylesheet
  links in DOM order. **`webengine_styles_open`** appends the inline text and
  the caller's already-fetched CSS as author sheets on top of its UA sheet.
  The renderer uses 800×600 CSS pixels at 96 dpi with 16px default text.
- **`webengine_style_element`** composes a selected style with its parent's.
  Web Viewer calls it while projecting the DOM into paragraphs.
- **`webengine_style_document`** selects every element's style in document
  order. It then composes the style with its parent's composed style
  (`css_computed_style_compose`), as libcss requires, and hands the result to
  a visitor. The walk keeps an explicit stack, so a deep document does not
  recurse.

### The selection handler

`webengine_select.c` is libcss' `css_select_handler` over libdom, written from
`libcss/select.h` and `docs/API`. These rules are easy to get wrong:

- **Element names.** libdom keeps HTML element names in upper case. The
  handler gives libcss lower-case names (`dom_string_tolower`) and compares
  without regard to case.
- **Borrowed nodes.** Every node handed to libcss is borrowed, not
  referenced. The document does not change during selection, and the tree
  keeps the node alive. `dom_element_named_ancestor_node` and
  `dom_element_named_parent_node` return a reference, whatever `element.h`
  says; the handler drops it. Keeping that reference leaked the whole
  document of every page with a descendant or child selector, which ASan
  found.
- **Ownership.** libdom's `dom_element_get_classes` keeps its array and
  gives one reference per class, which libcss releases. `node_name` and
  `node_id` return interned strings with a reference.
- **libcss' node data.** It lives in libdom's user data under one key.
  libdom's user-data handler tells libcss when a node is cloned, deleted,
  renamed, imported or adopted (`css_libcss_node_data_handler`).
- **Attribute selectors** follow Selectors level 3: values compare
  case-sensitively, and an empty value never matches `^=`, `$=` or `*=`.
- **`:empty`** fails on any element or text child, white space included.
- **`:lang()`** reads the nearest `lang=""`, with a dash-match that ignores
  case.
- **`:link`** is `a`, `area` and `link` with an `href`.
- **Form controls** have `:enabled`, `:disabled` and `:checked`, read from
  their attributes.
- **`:visited`, `:hover`, `:active`, `:focus` and `:target`** are always false.
  The engine has no history, pointer or focus yet.
- **User-agent defaults:** black text, sans-serif, no quotes.

The handler supplies legacy HTML color hints for the body, links and
`<font>` at the presentational-hint cascade level. The linked-sheet loader
and the UA stylesheet live in Web Viewer. Interactive selector state and
quirks mode remain deferred.

## Known costs

- **libcss' style sharing and sibling combinators.** With `+` or `~`, its
  style-sharing search can walk every earlier sibling of the same name. E3
  supplies a reusable, empty inline stylesheet when an element has no
  declarations. libcss then selects that node directly, keeping its normal
  combinator matching and avoiding the redundant sharing search. The SUN
  engine test exercises adjacent siblings on a 235 KiB document.
- **The heap was quadratic, and is not any more.** The C runtime's `malloc`
  walked every block, in use or free, so a DOM of a few thousand nodes took
  100 s to style in the guest. It now walks a list of free blocks only
  ([NATIVE_HEAP.md](../userland/NATIVE_HEAP.md#what-there-is)). The same
  page takes under a second.

## Tests

- **`webengine-test`** (host, `tests/host/webengine_test.c`) runs the shared
  self-test, then parses every `.html` page of the corpus
  (`tools/webview-test-www/`) and styles each one with its own `<style>`
  sheets. It checks that the walk met exactly as many elements as the DOM
  holds (`getElementsByTagName("*")`). Where the host compiler links
  AddressSanitizer, the test is built with it, and its leak checker fails the
  test when the glue keeps a reference that keeps a document alive.
- **`webengine-test`** (guest scenario, `/system/enginetest.sxe`) is a SUN PIE
  linking the SUN archives. It runs the same self-test, then a 235 KiB page
  of 8000 styled elements, which is past any fixed buffer and exercises the
  native heap. It ends with `ENGINE TEST PASS`.

The self-test, `webengine_selftest.c`, is one document with these checks:
- **Encoding and text.** A Windows-1252 `<meta>` placed after the first bytes
  wins, its curly quotes and `&eacute;` decode to UTF-8, and `&amp;` decodes.
- **Tree building.** HTML's implied end tags apply: `<ul>` closes an open
  `<p>`, and each `<li>` closes the last one. The parser inserts a table's
  `tbody`.
- **Selectors:** a class among several, an id with a child combinator but not
  a grandchild, `:first-child`, `+`, `:last-child` with a descendant,
  `:link`, `|=`, `:lang()` inherited from `<html lang>`, and `:empty`.
- **Values:** `style=""`, color inheritance, and `em` against the parent's
  font size (2em of 20px is 40px).
- **Errors.** Misnested markup, broken CSS and an empty page still parse and
  style.
